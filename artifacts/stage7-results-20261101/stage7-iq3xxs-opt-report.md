## 4. 해석

### 4.1 과거 S7-XXS-2와 직접 비교하면 안 되는 이유

과거 S7-XXS-2와 비교하면 모든 arm이 좋아 보입니다. 하지만 **Prefill에 영향이 없어야 할 Decode 전용 플래그 arm(10, 11)도 Prefill이 약 +1.2% 올랐습니다.** 세션 전체가 같이 움직인 것(페이지 캐시, 실행 시점 등)이며 플래그 효과가 아닙니다. 따라서 과거 기준 대비 비율은 인과 근거로 쓰지 않습니다.

- **Batch Wall**은 더 긴 쪽 에이전트의 생성 토큰 수가 좌우합니다. 같은 9번 arm 안에서도 200.29 s부터 214.81 s(xxs-9-2, B 2303 토큰)까지 벌어지므로 플래그 비교 지표로 쓰지 않습니다.
- **Decode tok/s**는 MTP draft 채택률과 출력 길이에 좌우됩니다. 같은 설정을 반복해도 출력이 달라지는 경우가 있습니다(예: 8번 A의 출력 해시 3개가 모두 다름).

### 4.2 Prefill — 같은 세션 안에서 비교

10·11번 arm은 SIMT=1이고 Decode 플래그만 바뀌었으므로 **같은 세션의 SIMT=1 Prefill 대조군**(6회)으로 사용했습니다. 두 플래그가 Prefill에 영향을 주지 않는다는 것은 업스트림 설명에 근거한 가정입니다.

| 구성 | Prefill A 중위값 (범위) | Prefill B 중위값 (범위) | 대조군 대비 |
| --- | --- | --- | --- |
| SIMT=1 대조군 (10+11, n=6) | 1004.65 (1002.5–1006.0) | 1011.8 (1010.1–1014.2) | — |
| S7-XXS-8 SIMT=2 | 1002.1 (1000.3–1002.3) | 1008.0 (1007.5–1011.3) | **−0.26% / −0.38%** (A는 범위가 겹치지 않음) |
| S7-XXS-9 GDN_REC_WARP=2 | 1005.9 (1004.6–1007.3) | 1014.3 (1011.2–1014.9) | +0.12% / +0.25% (범위가 겹침) |
| S7-XXS-12 prefill 4096 | 635.2 | 640.2 | **−36.8% / −36.7%** |

- SIMT=2는 이 워크로드에서 Prefill 개선이 없고, 오히려 소폭 느렸습니다.
- GDN_REC_WARP=2는 노이즈 범위 안에 있습니다. 업스트림 문서의 +6 ~ 9%는 GDN recurrence 커널 하나의 수치이고, 진단 로그상 이 커널은 IQ3_XXS 128K Prefill 시간의 약 4.4%(5.55 s)에 불과합니다. 이 플래그는 FP32 합산 순서를 바꾸며, 출력 품질 검증은 하지 않았습니다.
- `--prefill 4096`은 TTFT가 약 126 s에서 약 200 s로 늘었습니다. 두 배치 모두 같은 크기로 재현되어 3번째 배치 없이 종료했습니다.

### 4.3 Decode — 출력이 동일한 실행끼리 비교

서로 다른 arm인데도 **출력 해시, 생성 토큰 수, draft 채택 수가 완전히 같은 실행**이 여러 쌍 있었습니다. 같은 토큰열을 생성했으므로 디코드 시간(엔진 로그 `generated in … ms`) 차이는 커널 속도 차이로 볼 수 있습니다.

| 동일 출력 (생성, 채택/제안) | S7-XXS-8 SIMT=2 | S7-XXS-10 GATHER_WIDE=0 | S7-XXS-11 SM70_TABLE=1 |
| --- | ---: | ---: | ---: |
| B `42480474` (2059, 1119/1889) | 79,549 / 79,647 ms | 79,678 / 79,765 ms | **78,379 / 78,245 ms** |
| A `d542cf18` (1990, 1138/1815) | 76,011 ms | 76,141 ms | **74,606 ms** |
| B `80633a65` (1698, 916/1578) | — | 63,444 ms | **62,542 ms** |

- 같은 설정·같은 출력을 반복했을 때 디코드 시간 차이는 약 0.1%였습니다.
- **SM70_TABLE=1은 세 쌍 모두에서 다른 구성보다 1.4 ~ 2.0% 빨랐습니다.** 이번 스크린에서 일관된 Decode 신호는 이것 하나입니다.
- GATHER_WIDE=0과 SIMT=2는 +0.16 ~ 0.17% 차이로 구분되지 않습니다.
- **한계:** 출력이 같은 비교 대상은 SIMT=2(gather wide, table 없음), SIMT=1+GATHER0, SIMT=1+TABLE 세 구성입니다. 같은 세션의 순수 SIMT=1 Decode 대조군은 없습니다. 따라서 SM70_TABLE의 단독 효과는 "세 구성 중 가장 빠름"으로만 말할 수 있고, SIMT=1 대비 정확한 효과 크기는 직접 측정하지 않았습니다. GATHER0과 SIMT=2가 비슷한 것도 "둘 다 중립"일 수 있고 "효과가 서로 상쇄"되었을 수도 있습니다.
- 환경변수를 설정했다는 것만으로 해당 CUDA 커널이 실제로 실행되었다는 증거는 되지 않습니다. 엔진 로그에 플래그 적용 메시지는 없었습니다.

### 4.4 진단 (S7-XXS-DIAG-1, 비채점)

Agent A 기준 Prefill 126,960 토큰, GPU timeline 126.5 s의 구성:
- 비중이 큰 항목: gemm gate/up 21.8%, dequant 17.4%, gemm down 12.6%, qsa attn 8.3%, wait copy 6.6%, hc read 6.2%
- 이번 플래그들이 겨냥한 커널: qsa select 4.1%, gdn recurrence 4.4%

Decode는 window당 93.35 ms였고, 이 중 verify 79.40 ms 안에 **waitCPU(GDN 36.68 + QSA 7.19 ms)**가 가장 큽니다. 이번 플래그들이 겨냥한 커널(Prefill QSA select / GDN recurrence, Decode KV gather)은 각 단계에서 비중이 작기 때문에 전체 효과가 작게 나온 것과 일치합니다.
